## Enrolamiento sin identidad de dominio

`enrol.py` es herramienta efímera de operador, no método nuevo de autenticación ni componente Core. Servicio separado montara-pilot-enrol, read-only del runtime aprobado, sin acceso a state/Core config/token con InaccessiblePaths; secreto Google copiado privadamente a archivo regular 0600 de ese UID y retirado al terminar. No importa build_core, no DB, UUID, provisioning ni session Core. Usa OIDCSettings/OIDCProvider/read_client_secret ya instalados: HTTPS, backchannel sin redirect, code+PKCE S256, state/nonce, verificación RS256/JWKS/iss/aud/exp/iat y sub por adapter aprobado. Una ceremonia por proceso, code aleatorio 256 bits de operador (hash SHA256 en archivo root:grupo 0640, no en URL), consume una vez y expira 10 minutos máximo, pendiente hasta 5 minutos, máximo ocho intentos incorrectos. Cookie __Host-montara-login con Secure HttpOnly SameSite=Lax, borra en callback. Host/Origin exactos, JSON POST <=256 bytes, callback acotado, no caché, no referer, CSP, sin logging de solicitudes; respuesta no contiene sub, código Google ni token. POST devuelve URL de autorización al navegador; no se registra. No sesión persistente. Resultado único y privado en directorio temporal, archivo exclusivo 0600 O_NOFOLLOW. Root lee sólo después de detener el listener, por fd regular/no symlink, propietario y modo exacto, nlink=1, longitud/ASCII y unicidad; nunca interpreta el resultado como código. No se imprime el sub.

Access email y Google sub son cosas diferentes. Scope openid no certifica email; cada una de las cuatro personas recibe su código por canal privado y selecciona la cuenta Google confirmada, con confirmación explícita del operador sobre la cuenta que está seleccionando (no pedir tokens ni fotos con información sensible). No inferir sub a partir de email ni auto-link. Si no puede confirmarse la cuenta o resulta duplicada, detener. Este control humano es deliberado y no es una vinculación criptográfica del email Access con Google. No enviar códigos, IDs, JSON de credenciales ni resultados por chat/GitHub. El operador ve sólo el código efímero y marcadores, no el sub. Guardar 4 sub distintos en archivo privado root 0600; render-config aprobado genera TOML de Core, que sólo entonces provisiona UUID persistente cuando un usuario admitido inicia sesión real. El enrolador no tiene sesión Core ni cuenta de servicio de producto.

Se ha transferido un bundle JSON sin datos reales al workspace privado autorizado. Los 12 archivos del bundle son copia exacta del commit de preparación, no un ejecutable. El terminal del instalador se conecta a /dev/tty para prompts privados. No introducir secretos en el bloque.

```bash
sudo bash <<'SH'
set -Eeuo pipefail
umask 077
D=$(mktemp -d /root/montara-pilot-reviewed.XXXXXXXX)

  /srv/montara-core/workspaces/efrain/h2-10-install-bundle.json > "$D/bundle.json"

python3 -I - "$D" <<'PY'

from pathlib import Path

assert obj["format"]==1 and len(obj["files"])==len(names)
assert {x["name"] for x in obj["files"]}==names
for x in obj["files"]:
    b=x["content"].encode()
    assert hashlib.sha1(b"blob "+str(len(b)).encode()+b"\0"+b).hexdigest()==x["sha"]
    with (d/x["name"]).open("xb") as f:f.write(b)

test "$(git hash-object --no-filters "$D/install-pilot.sh")" = 0175794bf865e4a7ace932bf50759b2fe4bbf7ea

/bin/bash "$D/install-pilot.sh" "$D" </dev/tty >/dev/tty 2>&1
SH
```
