# Release Linux de referencia H2.7 — Core schema5 + Engine + OIDC

BRAIN #27. Base exacta `36b010c172370a9c59762cf355e782adc00c3de0`. Este documento y su guion son un gate de instalación temporal de ingeniería; no un despliegue de producción. [H2.6](README-h2.6.md) y sus manifiestos v4 permanecen históricos, sin modificación. No confundir este release con el siguiente worker/piloto de #28.

## Reproducción

Usar `reference-h2.7.sh` con HOME temporal privado, MONTARA_INPUT y MONTARA_OUTPUT separados y dedicados, usuario de pruebas no privilegiado, Ubuntu 24.04 x86-64, git, python3+venv, apt-get/dpkg-deb, openssl y acceso a repositorios oficiales para obtención separada. Adaptar solo el nombre del usuario de pruebas si se reproduce en otro host. No ejecutar sobre DB o medios reales. El input contiene dos archivos del gate histórico #25: `h2-27-v4-montara_core-0.1.0-py3-none-any.whl` y `h2-27-v4-published-fixture.mp4`. Verificar hashes contra manifest y calidad #25, obtener los artefactos históricos autorizados o reconstruirlos mediante el procedimiento histórico si no están disponibles. No publicar binarios upstream. El wheel histórico reconstruido debe coincidir; el archivo publicado utilizado debe coincidir en SHA256. No volver a renderizar v4 en este gate.

Reutilizar el procedimiento de extracción local de FFmpeg/ffprobe 6.1.1 de H2.6 y los 148 pares exactos paquete=versión del lock v4. Comparar hashes de .deb, ejecutables y bibliotecas host, detener ante drift. No apt install ni scripts de mantenimiento. Python 3.12.12 mediante uv 0.9.18 (wheel verificado), conservar pines y SHA256 históricos de los 16 paquetes Engine/QA y 2 build, añadir PyJWT 2.15.1, cryptography 50.0.2, cffi 2.1.1 y pycparser 3.12, verificar wheelhouse y resolver extra oidc sin acceso a índices durante instalación. Los hashes de los cuatro wheels nuevos se registran al descargar para esta ejecución, no son atestación externa; los siguientes rebuilds deben cotejarlos con el lock publicado. El bootstrap Python/host no es una imagen hermética. Dos exports/builds de v5 con SOURCE_DATE_EPOCH y toolchain fijada, instalar desde wheel en venv independiente; no copiar venv ni distribuir Engine. Pines renderer y Engine permanecen los de #25.

## Piloto autenticado: contrato con Archi

[OIDC H2.5](../docs/oidc-http-h2-5.md), BRAIN #28. El siguiente gate de worker e interfaz mínima de ingeniería es trabajo de Archi. Mantener separación de worker confiable y HTTP, claim/fencing/recuperación de Core, pines externos, misma DB y roots absolutos, un job cada vez; no añadir endpoint privilegiado. Configuración [oidc] externa: issuer, authorization_endpoint, token_endpoint, jwks_uri, client_id, client_secret_file absoluto canónico regular del UID de servicio 0600, public_origin HTTPS exacto. No secretos en GitHub/argv/env/TOML, no reutilizar clientes V1. Solo tras autorización FER: cliente Google OAuth Web aislado, cuentas de prueba admitidas, callback exacto /auth/callback, proxy TLS con Host preservado y backend loopback, sin cache/log de query/cookies/codes; medidas de admisión/tasa/recursos conforme a #28. No crear cliente, publicar endpoint ni habilitar TLS público aquí. No autolink de cuentas internas antiguas. Configuración del worker se precisará en #28 antes del release final de piloto.

## Medición

Mismo criterio de #25: wall monotónico, CPU de proceso y descendientes recolectados, RSS aproximado del árbol y memoria cgroup (incluye cache), muestreo 200ms, bytes lógicos del state y delta FS. No benchmark ni extrapolación a seis horas. Reportar fases de bootstrap, instalación, migración, OIDC, AV, reinstalación. Evidencia saneada, no publicar rutas de acceso, IDs de cuenta, credenciales ni logs crudos.
